# Editing Resources #17 — Export, Social Platforms & Accessibility

> Deliver clear, readable videos that survive mobile compression and platform UI.

**Scope:** 36 practical techniques and editorial concepts, grouped into 3 sections. Some are established film/postproduction terms; others are explicitly descriptive workflows rather than formal industry jargon.

**Application:** Roblox / Anime Breaker Shorts, faceless gaming guides, tutorials and challenge videos.

## Export fundamentals

| Technique / method | Short explanation | Roblox or faceless-video use |
|---|---|---|
| **Aspect ratio** | Proportion of frame width to height | Vertical 9:16 for typical Shorts |
| **Resolution** | Pixel dimensions of export | 1080x1920 when source quality supports it |
| **Frame rate** | Number of frames per second | Match source or choose consistent 30/60 |
| **Codec** | Method used to compress audio/video | H.264 broadly compatible for uploads |
| **Container** | File structure holding encoded streams | MP4 commonly accepted |
| **Bitrate** | Encoded data allocated per second | Balance file size and detail |
| **Variable bitrate** | Spend more data on difficult frames | Efficient for complex effects |
| **Constant frame rate** | Even frame timestamps | Avoid audio drift in some workflows |
| **Keyframe interval** | Frequency of fully decoded frames | Helps seeking and playback |
| **Audio sample rate** | Digital audio samples per second | 48 kHz is a common video choice |
| **Audio codec** | Encoded audio method | AAC works broadly in MP4 |
| **Loudness consistency** | Keep subjective volume across uploads | Avoid one Short noticeably louder |

## Mobile and accessibility

| Technique / method | Short explanation | Roblox or faceless-video use |
|---|---|---|
| **Action-safe area** | Reserve edge space for important elements | Keep boss and captions away from UI overlays |
| **UI awareness** | Consider platform buttons/captions blocking corners | Avoid a code in right-side controls |
| **Caption proofread** | Correct proper nouns and numbers | Prevent wrong code in description |
| **Text readability test** | Inspect on actual phone at normal size | Make HP values decipherable |
| **Contrast check** | Ensure readable text against footage | Add subtle plates or outline |
| **Color independence** | Do not convey key meaning only through color | Pair green/red with labels |
| **Flashing restraint** | Avoid rapid intense flashes | Reduce photosensitivity risk |
| **Motion restraint** | Avoid continuous shaking during instruction | Reduce visual discomfort |
| **Audio clarity** | Voice audible on basic phone speakers | Make directions understandable |
| **Thumbnail/cover frame** | Choose representative readable still | Boss and clear headline |
| **First frame quality** | Make opening clear without waiting for fade | Hook immediately |
| **Muted comprehension** | Viewer can understand essential points silently | Captions and arrows carry message |

## Publishing quality assurance

| Technique / method | Short explanation | Roblox or faceless-video use |
|---|---|---|
| **Source review** | Check for capture glitches before edit | Avoid exporting corrupted footage |
| **Export playback** | Watch exported file, not only timeline | Catch missing audio or freezes |
| **Crop check** | Test full vertical frame | Do not cut off avatar or UI |
| **Compression check** | Look for banding and blockiness | Dark scenes remain readable |
| **Metadata check** | Ensure correct duration, fps and orientation | Avoid sideways upload |
| **Description accuracy** | Verify names, links and instructions | Codes match actual game |
| **Platform rules review** | Follow community and copyright requirements | Avoid unlicensed music and misleading claims |
| **Upload preview** | Check how captions and UI overlay content | Reposition future templates accordingly |
| **Archive original** | Save project and high-quality final | Make later revisions possible |
| **Audience feedback** | Note what viewers struggled to see | Improve next upload |
| **Caption language** | Match viewer's preferred language | Accessibility and search |
| **Final sign-off** | No missing clips, wrong stats or accidental secrets | Publish confidently |

## Ready-to-use example

Export routine: choose 9:16 canvas -> verify on-screen text has safe margins -> export MP4 at sensible quality -> play the result on phone -> inspect sound, legibility, and last frame -> upload.

## Avoid these mistakes

- Upscaling low-quality gameplay expecting true new detail
- Choosing 60 fps when source cannot supply it
- Placing text underneath platform buttons
- Failing to watch the actual exported MP4

## Final review checklist

- [ ] Is the format correctly oriented?
- [ ] Are text and UI unobstructed?
- [ ] Does audio play cleanly?
- [ ] Are numbers and codes correct?

## Working notes

- In CapCut, exact feature names and availability can vary by platform and app version.
- A digital crop, blur or keyframe animation may simulate a movement but cannot reconstruct missing 3D camera perspective.
- For stats, codes and release-specific claims, verify the footage/game before publishing.
- Use original, licensed or otherwise permitted audio and visual assets.
